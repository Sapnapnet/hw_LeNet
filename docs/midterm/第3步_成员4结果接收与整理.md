# 第3步：成员4结果接收与整理

完成日期：2026-09-07。范围：按获批方案整理成员4Conv1/Conv2的综合与验证交付；成员4补充的朴素基线说明已纳入，无需再次审核方案。第3、4步整体仍为部分完成。

## 1. 完成内容

已使用用户指定的两份`conv*_baseline_csynth.rpt`作为基线，采用final目录的两份最终版报告，形成原始综合指标表、重新计算的变化表、两张对比图和结果说明。已沿用无明确冲突的交付配置、接口及验证记录，并区分报告数值、成员4说明、代码可核查的实现方式。

已记录：基线为最初朴素卷积，与最终版结构不同，来源为成员4经用户转述。因此结果属于两种实现整体对比，未将变化归因于某一项优化。原说明的旧基线及依赖旧基线的比例不采用，原文件保持不变。

核心结果：Conv1延迟下降61.23%，Conv2下降92.49%；Conv1 LUT下降23.57%，Conv2 LUT增加659.86%，两层FF、DSP均增加。详见[成员4结果汇总](../results/midterm/member4/conv_optimization_summary.md)。

## 2. 方法

1. 对成员4交付目录的143个原始文件计算SHA256，记录当前接收内容；不改写旧MANIFEST，不重建其代码版本。
2. 使用临时JavaScript程序提取四份报告的顶层资源Total行、Latency、Interval、时钟及元数据；保留报告行号与来源ID。子实例资源未当作顶层数据使用。
3. 将指标写入Artifact Tool表格，按最终版减基线计算增减量与比例。以未舍入的cycles计算延迟下降率和比值，基线为0的百分比留空并说明不适用。导出两份UTF-8 CSV，回读检查数据和计算关系。
4. 用与已提取数据关联的图表生成资源、延迟PNG，检查数量、单位、图例和布局。临时程序及检查预览不作为项目交付物。
5. 根据代码中的模板参数、循环、数组分割和条件分支说明已有实现。申报测试结果注明成员4来源；未运行模型、测试脚本、C Simulation或综合。
